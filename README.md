# FailureLens

**Finding the Hidden Failures** — a framework for detecting, grouping, and prioritizing failures in AI-agent conversations, built for SupplyzPro's "Come Build with AI" hackathon challenge.

> We don't just find bugs in AI-agent conversations — we group them by root cause, rank them by real impact, and prove a fix works.

## The problem

Most agent failures never throw an error. A tool call "succeeds" with an empty or wrong result, the agent smooths it over with a confident sentence, and the only trace is a customer getting the wrong answer. FailureLens finds that gap between what a tool returned and what the agent claimed — not just counts of exceptions.

## Pipeline

1. **Ingest** — normalize synthetic SupplyzPro agent conversations (inventory checks, purchase orders, supplier lookups, shipment tracking) into a single event stream.
2. **Detect, in layers**
   - `pipeline/rules.py` — explicit error codes, timeouts, and identical repeated tool calls (retry loops).
   - `pipeline/llm_judge.py` — an LLM-as-judge that compares each tool call's raw response against the agent's next message to catch hallucinated claims and wrong-target tool calls.
   - `pipeline/behavioral.py` — dropped constraints (context collapse) and repeated user rephrasing (frustration signal).
3. **Cluster by root cause** (`pipeline/cluster.py`) — TF-IDF + KMeans over each failure's description, so failures are grouped by underlying cause, not surface symptom.
4. **Prioritize** (`pipeline/prioritize.py`) — `Priority Score = Frequency × Severity × Blast Radius`, a transparent, auditable formula.
5. **Close the loop** (`pipeline/regression_probes.py`) — for the #1 cluster, auto-generate a small regression-test suite, confirm the detector catches it, and compare that cluster's frequency before vs. after a simulated fix.
6. **Present with evidence** (`app.py`) — a Streamlit dashboard with the ranked clusters, real transcript evidence per cluster, and the before/after fix chart.

## Project layout

```
data/
  generate_conversations.py   # synthetic data generator
  conversations_before.json   # bug present (no idempotency check on retries)
  conversations_after.json    # bug patched
pipeline/
  rules.py                    # layer 1: rule-based detection
  llm_judge.py                # layer 2: LLM-as-judge (NVIDIA NIM, with offline fallback)
  behavioral.py                # layer 3: behavioral signals
  cluster.py                  # groups failures by root cause
  prioritize.py               # Frequency x Severity x Blast Radius
  regression_probes.py        # generates + verifies regression tests for the top cluster
  run_pipeline.py             # orchestrates everything, writes results/*.json
results/                      # pipeline output, read directly by app.py
app.py                        # Streamlit dashboard
```

## Setup

```bash
pip install -r requirements.txt
cp .env.example .env   # optional: add NVIDIA_API_KEY to use a live NIM model as the judge
```

## Running it

```bash
# 1. (re)generate the synthetic conversation datasets
python data/generate_conversations.py

# 2. run detection -> clustering -> prioritization -> regression probes
python -m pipeline.run_pipeline

# 3. launch the dashboard
streamlit run app.py
```

`results/` and `data/*.json` are committed, so `streamlit run app.py` works immediately without running steps 1-2 first — only re-run them if you change the generator or detection logic.

## NVIDIA integration

The LLM-as-judge layer (`pipeline/llm_judge.py`) calls NVIDIA's hosted NIM chat-completions API when `NVIDIA_API_KEY` is set (get one at [build.nvidia.com](https://build.nvidia.com)). Without a key, it falls back to a deterministic offline heuristic that checks the same two things (claimed numbers match the tool's response, claimed entity matches the one requested) — so the full pipeline is reproducible without any external dependency, and swapping in a live model is a one-line env var change.

## Deploying

Push this repo to GitHub, then deploy `app.py` on [Streamlit Community Cloud](https://streamlit.io/cloud) — point it at this repo, `app.py` as the entry point, and add `NVIDIA_API_KEY` under app secrets if you want the live LLM judge instead of the offline fallback.

## Disclosure

All conversation data on this dashboard is **synthetic**, generated by `data/generate_conversations.py` to represent plausible SupplyzPro workflows with deliberately seeded failure patterns. AI tools used: an LLM-as-judge (NVIDIA NIM-hosted model, or an offline heuristic fallback) for hallucination/wrong-target detection, and TF-IDF/KMeans for unsupervised root-cause clustering.

## Limitations and next steps

- Runs on synthetic data. Applied to real conversation/tool-call logs, the LLM-as-judge rubric should be validated against a hand-labeled sample before trusting it at scale.
- Severity and blast-radius weights are currently fixed; they should be tuned with input from the team that owns each workflow.
- The before/after comparison here is a simulated fix on a second synthetic batch — in production, a cluster's score would be tracked over time against the real system to verify a fix actually worked.
